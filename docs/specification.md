## 入力契約

0.3.3から表示領域の幅・高さをCSSピクセルで取得し、ページとゲーム面を固定する。スマホの高さだけのresizeはアドレスバーやキーボードの伸縮として扱い、ゲーム面を変更しない。幅が変わったとき・画面回転・履歴からの復帰では再取得する。PCはウィンドウのresizeに追従する。短い画面向けのレイアウトも、固定した高さをコンテナークエリーで判定する。

全要素に `touch-action: manipulation` を設定し、プレイ・カウントダウン中のゲーム面全体は `none` とする。塔・余白・HUDを含む連続タップの拡大を抑える。[touch-actionの仕様説明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。ページ全体はスクロールせず、ランキング・動物選択・設定・開始画面・結果画面は必要な範囲で内部スクロールできる。名前入力時には可視領域の高さを使って結果画面内をスクロールし、キーボードで入力欄が隠れないようにする。

Pointer Eventsの新規 `pointerdown` を1回だけ受ける。互換 `click(detail > 0)` は採点しない。押し続けた同一ポインターは重複採点しない。`pointerup/cancel` で解放する。異なる指は個別に受け付け、同時入力はブラウザから届く順に判定する。ボタン外からスライドして入るだけでは入力にならない。

左右/A/Dの新規keydownを受け、OSリピートは捨てる。ボタンにフォーカスしたEnter/Spaceも新規keydownを1回受ける。支援技術による `click(detail = 0)` はボタン活性化として受け付ける。設定ダイアログ操作中は採点しない。

高頻度タップでエフェクトが増え続けないよう描画オブジェクトを固定プールにする。得点と駒の列は描画状態から独立して進む。入力ログはラウンドあたり4096件に制限し、シード・入力・単調時刻から同じ結果を再生できる。

## ランキングの保存と限界

Cloudflare D1へ匿名の端末ID、参加トークンのハッシュ、公開ニックネーム、最高得点・正解数・最大コンボを保存する。参加トークンはそのブラウザだけで保持し、一覧へ返さない。ブラウザの保存内容を削除した場合や別のブラウザでは別参加者になる。全国という表示は公開参加者の共通ランキングを意味し、居住国や都道府県の確認は行わない。

0.3.1から `src/ng-names.json` のNGワードを含む新規ニックネームをサーバーとクライアントで拒否する。0.3.2で265語を8分類へ拡充。日本語の卑語・排泄語・罵倒・脅迫・差別語・薬物表現、英語とローマ字表記を扱う。NFKC正規化、カタカナからひらがなへの変換、小書きかなの統一、空白・記号・長音の除去を行って照合する。日本語は部分一致、短く曖昧な罵倒語は名前全体の一致、英語・ローマ字はラテン文字の単語境界を使う。パチンコ・うんちく・シネマ・やくそくなどの例外は該当箇所だけを保護し、名前の他の部分にあるNG語は判定する。詳細は [name-policy.md](name-policy.md) を参照。辞書方式であり、全ての隠語や表記の偽装、意味・文脈を網羅するものではない。

既存名は一覧取得時にNG語の文字だけを半角 `*` へ変換する。例: `おまんこ → お***`、`うんこ太郎 → ***太郎`。区切り記号・空白と名前の残りは保持する。結合文字や半角濁点は基底文字と一緒に扱い、見た目の1文字を1つの `*` にする。全体・スマホ・PCの全種類へ適用する。DBの元記録は変更せず、ID・得点・正解数・コンボ・達成日時・順位を保つ。公開応答には `namePolicyVersion` を付け、同じ版のクライアントは伏字の再処理を行わない。古いAPI応答とローカルに保存された元の名前にはクライアント側で表示処理を適用する。NG名で登録を拒否した際はラウンドを消費しないため、別名に直して再登録できる。

0.3.0から端末種別をラウンド発行時に保存し、`device_scores` に参加者×スマホ/PCの自己ベストを保存する。全体は従来の `players` の最高記録を維持する。旧版の得点・ラウンドは情報がないため端末別へ推測して移さない。`/api/ranking?category=all|mobile|pc` で一覧を取得し、省略時は全体。旧クライアントにも互換を維持する。

ブラウザの端末情報からスマホ・タブレットをスマホ、その他をPCとして判定する。タッチ対応PCをタッチ数だけでスマホにしない。iPadOSのMac形式の識別情報にはタッチ数を併用する。種別はラウンド開始後に変更できないが、ブラウザの識別情報の偽装を防ぐ仕組みではない。

サーバーで発行したラウンドID・シードから入力履歴を再生し、送信された得点値は使用しない。40秒未満、10分以上経過、中断、再使用されたラウンドによる最高記録の更新を拒否する。1ラウンドの履歴は2500入力、正解は1200回までとし、参加者・IP単位の要求回数も制限する。IPは日付ごとのハッシュのみ短期のレート制限へ保存し、生のIPはDBへ保存しない。

0.3.4からルール版3を発行し、4連続制限をクライアントとサーバーの両方で使用する。ラウンドへ `rules_version` を保存し、更新前の版2の未登録ラウンドは従来の制限なしの列で再生する。既存の最高記録は変更しない。

0.3.5のAutoResetでは未登録の同じラウンドIDを使い、発行シードと試行番号から `src/attempt.ts` で新しいシードを算出する。前回の開始時とミス直前と同じ6段になる候補は番号を進めて再抽選する。左右の動物は最初に選んだ組を維持し、各列の最大4連続も維持する。ミスのたびに発行APIへ要求しない。登録時は最後の試行番号と履歴だけを送り、サーバーも発行シードと番号から再生する。クライアントの任意の得点値・シード値を採用しない。試行番号は0〜4294967295の整数とし、版2のラウンドで0以外は拒否する。APIの `autoResetVersion: 1` を確認できないときは、リセット後を端末内の記録だけにして再読込を案内する。0.3.4以前のクライアントは番号を送らず、0番の従来の記録として登録できる。登録期限は初回発行から10分のままで、期限切れは新しいゲームを開始する。

入力再計算は単純な得点改ざんへの対策であり、自動操作や複数ブラウザ・参加IDの取得を完全に防ぐ仕組みではない。賞金などを伴わないカジュアルなランキングとする。ラウンド履歴のDBには入力列自体を保存せず、シード・発行時刻・利用済み状態を1日保持してから削除する。
